# Lumina

Графики электроснабжения Запорожской области: Telegram → `scraper.py` → `schedule.json` → статический сайт.

## Аварийный режим

Парсер независимо от ГПВ распознает явные сообщения о введении и отмене ГАВ/СГАВ: сокращения, полные названия, украинские и русские формулировки. Состояние каждого режима сохраняется до его явной отмены. Обычный пост с расписанием, смена даты, отсутствие новых сообщений или ошибка сети не снимают аварийный статус. Частичная отмена для отдельных очередей не считается полной отменой режима.

Сообщения упорядочиваются по времени действия/публикации и ID Telegram. Редактирование того же поста повторно обрабатывается. Условные предупреждения («можливе», «якщо», «будуть») не считаются фактом введения. Для явных указаний «з 14:00» в день публикации изменение применяется при первом опросе после указанного времени. Это консервативный текстовый парсер, а не понимание любых формулировок: новые варианты следует закреплять тестами.

При ГАВ/СГАВ сайт:

- показывает общее предупреждение и исходное сообщение оператора со ссылкой;
- заменяет прогноз городом с огнем на крышах, дымом и отражениями на воде;
- скрывает обратный отсчет, расчетные окна и приостанавливает напоминания о переключениях;
- оставляет исходные ГПВ в раскрываемом блоке и обзоре очередей для ознакомления;
- помечает график в визуализаторе и экспортируемом PNG как предварительный;
- возвращает обычный режим только после отмены всех известных активных ограничений.

Анимация условная и не сообщает о реальных пожарах. При `prefers-reduced-motion` движение отключается. При отсутствии сети сохраненный статус не считается заново проверенным.

## Формат данных и обновление

Массив дней и поля `date`, `queues`, `versions` сохранены. Поле `emergency` находится в первом элементе массива и относится ко всей области, независимо от даты выбранного графика. Оно содержит `active`, `regimes.gav` / `regimes.sgav`, текст и время сообщения, ссылку на источник. При отсутствии расписания допускается запись с пустым `queues` для передачи аварийного статуса.

Вся логика парсера остается в `scraper.py`, без новых зависимостей. Существующий Ubuntu-обновлятор, который забирает `main` перед запуском и отправляет только `schedule.json`, подхватит изменение после слияния. Для установленной ранее службы можно запустить проверку вручную:

```bash
sudo systemctl start lumina-update.service
sudo journalctl -u lumina-update.service -n 50 --no-pager
```

Период проверки источника задается серверным таймером (в прежней установке — 5 минут) либо GitHub Actions. Сайт проверяет JSON раз в минуту. Задержка GitHub Pages добавляется к этим интервалам. Аварийный статус определяется последними полученными сообщениями и не является показанием датчика света.

## Проверки

```bash
python -m pip install requests beautifulsoup4
python -m unittest -v test_scraper test_emergency
node test_my_queue.cjs
```

Тесты проверяют исходные примеры введения/отмены, варианты текста, частичную отмену, хронологию, правку поста, сохранение расписаний при обновлении только статуса, совместимость с Ubuntu-оберткой, отключение таймера/напоминаний и восстановление обычного интерфейса.
